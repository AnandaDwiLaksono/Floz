- Current repository code and tests, including relevant uncommitted changes, establish implemented behavior. Official FLOZ specifications govern their respective product, API, database, architecture, and UI contracts; surface conflicts rather than silently reconciling them.
- Consult Obsidian only for relevant project history, engineering rationale, prior debugging lessons, or cross-module decisions. Historical notes provide context, not proof of current behavior; test existence does not prove execution or success.
- Resolve `OBSIDIAN_VAULT_PATH` through the Hermes Obsidian Skill using the supported terminal runtime. Never preload the Vault. Search relevant filenames/headings, then read focused sections; skip retrieval when existing evidence suffices.
- Reuse valid retrieved context; refresh when relevant evidence changes or becomes unavailable. Expand investigation whenever security, RBAC, workspace isolation, debugging, or QA needs more evidence; impose no arbitrary retrieval limits.
- Standing authorization permits Hermes to update FLOZ knowledge notes only within the Vault's existing top-level folders numbered `01`–`07`, subject to task-specific restrictions. It excludes `08-Source-Documentation`, Obsidian/Hermes configuration, and memory.
- After each completed FLOZ development task, evaluate write-back; write only important, reusable, verified knowledge not already documented: approved architecture/UI/UX decisions, bugs with validated root causes and fixes, significant milestones, regression risks, security findings, or verified operational procedures. Skip minor changes, duplicates, and unverified conclusions.
- For eligible knowledge, search related filenames/headings and read focused sections; update canonical notes, creating a note only when necessary. Include sources, verification status, date, and commit SHA when relevant; distinguish uncommitted evidence. Read back each written note to verify the result.
- Perform write-back within the current task workflow, never through separate automation or background jobs. Never read the entire Vault, automatically synchronize the repository, inject Vault knowledge into persistent memory, or store secrets in knowledge notes.
- For development tasks, report one line: `Knowledge: UPDATED (path) / SKIPPED (alasan) / BLOCKED (kendala)`; select the applicable status.
